# Gaming-Room-design
# CS 230 Portfolio Reflection: The Gaming Room

## 1. Client and Software Requirements

The client for this project was The Gaming Room. They wanted to expand their existing game, Draw It or Lose It, into a web-based application that could run on multiple platforms. The software needed to support multiple teams and players, unique game and team names, and multiple game sessions. It also needed to prevent duplicate game and team instances. The design had to consider operating platforms, memory management, storage, and security.

## 2. What I Did Well

I did well at organizing the information into different sections, including the requirements, system architecture, and platform recommendations. I focused on making the document understandable for both the client and the development team. This helped me explain the technical decisions behind the proposed software.

## 3. What I Found Helpful About the Design Document

Working through the design document helped me understand the project requirements before thinking about implementation. It gave me a clearer idea of the system's structure, the classes needed, and how different parts of the application would work together. Having a plan also made it easier to identify possible problems early.

## 4. What I Would Revise

If I could revise one part of my work, I would improve the comparison of operating platforms. I would provide more details about the advantages and disadvantages of each option and explain more clearly why the recommended platform would meet the client's needs. This would make the final recommendation stronger.

## 5. Considering the User's Needs

I interpreted the client's needs by focusing on a multiplayer game that could be accessed through different platforms. I included requirements for managing games, teams, and players while preventing duplicate names and instances. Considering user needs is important because the software should solve the actual problem and be easy to use. It also helps developers avoid building features that do not support the client's goals.

## 6. My Approach to Software Design

My approach to software design is to understand the requirements first, break the problem into smaller parts, and plan how the components will work together. In future projects, I would use techniques such as requirements analysis, UML diagrams, class diagrams, and platform comparisons. I would also review the design against the client's requirements before beginning development.
